# التحكم في الروتر — Router Control v1.0.0

تطبيق أندرويد للتحكم في روتر **ZTE ZXHN H288A** (سوفت H288A V1.0_GR5.1T16) من الموبايل،
بدل ما تفتح صفحة الروتر كل مرة.

- Package: `com.routercontrol.app`
- الإصدار: versionCode **1** / versionName **1.0.0**
- minSdk 26 / targetSdk 35 / AGP 8.7.3 / Gradle 8.9
- الواجهة عربي (RTL) بالكامل.

## المميزات (v1)

1. **القواعد (Parental Controls):** قايمة القواعد الستة بأسمائها وزرار On/Off لكل قاعدة.
   On = القاعدة شغالة = الجهاز محظور طول اليوم. Off = الجهاز مفتوح.
2. **مين أونلاين:** قايمة الأجهزة المتصلة دلوقتي (واي فاي + سلك) بالاسم والـ IP والـ MAC،
   وزرار حظر جنب كل جهاز. لو الجهاز ليه قاعدة، الزرار بيقلبها؛ ولو جديد، بيتعمل له
   قاعدة حظر جديدة (Ban Internet Access، كل يوم، 00:00–23:59).
3. **الجدولة:** حظر تلقائي في وقت محدد لكل قاعدة (مثال: 23:00–07:00)، كل يوم أو
   أيام الدراسة (الأحد–الخميس) أو الويك إند (جمعة+سبت). بتتنفذ كل ربع ساعة.
4. **التايمر:** افتح جهاز محظور لمدة 30 دقيقة أو ساعة، وبعدها يتقفل لوحده.
5. **اقفل الكل (وضع النوم):** زرار واحد يحظر كل القواعد.
6. **قفل التطبيق بـ PIN:** رقم سري 4 أرقام لفتح التطبيق، عشان العيال ما يفكّوا الحظر.
7. **التشخيص:** صفحة بتفحص عنوان صفحة التحكم الأبوي في الروتر (شوف قسم "اللي لسه غير مؤكد").

## الإعداد (أول مرة)

1. ثبّت الـ APK وافتح التطبيق وانت متصل بواي فاي البيت.
2. من صفحة **الإعدادات**: اكتب عنوان الروتر (الافتراضي `192.168.1.1`) واسم المستخدم
   (`admin`) وباسورد الأدمن، ودوس حفظ.
3. عيّن رقم سري (PIN) 4 أرقام للتطبيق — هيتطلب منك كل مرة تفتح التطبيق.
4. دوس **تحديث** في صفحة القواعد أو مين أونلاين عشان التطبيق يسجّل دخول للروتر
   ويجيب الأجهزة.
5. اربط كل قاعدة بجهازها: من صفحة مين أونلاين، دوس "ربط الجهاز ده بقاعدة موجودة"
   واختار اسم القاعدة. (القواعد الستة محفوظة بأسمائها من الأول: Ahmed، Rasha،
   Desktop، My TV، Tablet، Hyper — بس من غير MAC، لازم تربطها بنفسك عشان الـ MAC
   بتاعك ما يتحطش في الكود.)

## تنبيهات مهمة

- التطبيق بيشتغل على **واي فاي البيت بس** — الروتر مش بيفتح صفحته من برّه البيت.
- **الماك العشوائي:** الموبايلات اللي مفعّلة الـ Private MAC / Random MAC ممكن
  تهرب من الحظر، لأن الروتر بيحظر بالماك. ثبّت الماك من إعدادات الواي فاي على
  جهاز العيال (Use device MAC).
- باسورد الروتر والـ PIN محفوظين على موبايلك بس (DataStore)، ومبيتبعتوش لأي حد،
  ومش موجودين في الريبو إطلاقا. الـ PIN محفوظ كهاش SHA-256 مش كنص.

## الـ API — المتأكد منه واللي لسه غير مؤكد

المصدر الأساسي: مكتبة `juacas/zte_tracker` (Home Assistant) — عيلة H288A متأكدة فيها،
وملاحظات الهندسة العكسية بتاعتها على GitHub.

| الحاجة | العنوان / الطريقة | الحالة |
|---|---|---|
| تسجيل الدخول | `GET /?_type=loginData&_tag=login_token` (توكن رقمي من XML) ثم `GET /?_type=loginData&_tag=login_entry` (sess_token) ثم `POST` بنفس العنوان بـ `action=login&Username=&Password=SHA256(password+token)&_sessionTOKEN=` | ✅ متأكد |
| الأجهزة (واي فاي) | `GET /?_type=menuData&_tag=accessdev_ssiddev_lua.lua` — الأجهزة في `OBJ_ACCESSDEV_ID` | ✅ متأكد (عيلة H288A) |
| الأجهزة (سلك) | `GET /?_type=menuData&_tag=accessdev_landevs_lua.lua` — نفس العنصر | ✅ متأكد |
| الأجهزة (بديل) | `GET /?_type=menuData&_tag=wlan_client_stat_lua.lua` — `OBJ_WLAN_AD_ID` | ✅ متأكد (عيلة F6640، بديل بس) |
| الجلسة | كوكي SID + guid = الوقت بالمللي ثانية ويزيد مع كل طلب | ✅ متأكد |
| التحكم الأبوي: اسم السكربت | مرشحات: `internet_parental_lua.lua` / `security_parental_lua.lua` / `parental_lua.lua` | ❌ **غير مؤكد — تخمين من نمط تسمية ZTE** |
| التحكم الأبوي: بارامترات الـ POST | `IF_ACTION=Apply` + `Name` + `UserIdentity` (الماك) + `Enable` + `Action` + وقت البداية/النهاية | ❌ **غير مؤكد** |
| إنشاء قاعدة جديدة | `IF_ACTION=Add` + نفس الحقول | ❌ **غير مؤكد** |

**مفيش مصدر عام بيغطي التحكم الأبوي في ZTE** (مكتبة zte_tracker بتعمل تتبع أجهزة
وريبوت بس). عشان كده التطبيق:
- مش بيدّعي أبدا إن التغيير وصل للروتر إلا لو رد الروتر فيه `SUCC`.
- لو العنوان مش مؤكد، التغيير بيتحفظ محليا وبيتعلّم عليه "لم يؤكد الروتر".
- صفحة **التشخيص** بتجرّب المرشحات وبتعرض كود HTTP ورد الروتر لكل واحد،
  وبتحفظ أول عنوان شغال في الإعدادات.
- في الإعدادات خانة "عنوان صفحة التحكم الأبوي (متقدم)" — لو عرفت الاسم الحقيقي،
  اكتبه هناك ومش هتحتاج نسخة جديدة.

### إزاي تجيب العنوان الحقيقي (لو التشخيص ما لقاهوش)

1. من كمبيوتر على نفس الشبكة، افتح صفحة الروتر في Chrome، وافتح DevTools (F12) > Network.
2. روح Internet > Parental Controls، وقلّب زرار On/Off لقاعدة واحدة.
3. في Network هتلاقي طلب فيه `_tag=....._lua.lua` — ده اسم السكربت الحقيقي.
4. اكتبه في خانة الإعدادات في التطبيق.

## اللي لسه محتاج اختبار على الروتر الحقيقي

1. تسجيل الدخول على روتر H288A V1.0_GR5.1T16 (السوفت المعدّل) — الخطوات متأكدة
   من مكتبة عامة، بس السوفت المعدّل ممكن يختلف في تفصيلة.
2. قايمة الأجهزة (WLAN + LAN) — متوقع تشتغل، لازم تتأكد بالأسماء والـ IP.
3. **تفعيل/تعطيل قاعدة من التطبيق، والتأكد من صفحة الروتر إن الزرار اتقلب فعلا.**
   ده أهم اختبار في v1 — جرّبه على قاعدة واحدة الأول (مثال: Desktop).
4. إنشاء قاعدة جديدة من صفحة مين أونلاين لجهاز جديد.
5. الجدولة والتايمر (بتعتمد على نجاح 3).

## البناء على GitHub

الريبو بيتبني بـ GitHub Actions (`.github/workflows/main.yml`) — نفس نمط AssetSmart:
بناء Release بدون توقيع جوّه Gradle، وبعدين توقيع بـ apksigner في الـ workflow،
والأرتيفاكت اسمه **RouterControl-APK**.

الـ 4 Secrets المطلوبة في الريبو (نفس توقيع المستخدم الثابت):
- `KEYSTORE_BASE64` (3612 حرف — الصقه على 4 أجزاء وتأكد من العدد قبل الحفظ)
- `KEYSTORE_PASSWORD`
- `KEY_ALIAS` = `nova`
- `KEY_PASSWORD`

خطوة "Verify keystore" في الـ workflow بتتأكد من حجم المخزن (2708 بايت) والاسم
والبصمة (SHA-256: 26:85:F7:C2:…:C0:AF) قبل البناء.

ارفع **محتويات** مجلد `RouterControl` ده في جذر الريبو (مش المجلد نفسه)،
وأي Push على main يبني APK موقّع.

## البناء محليا (اختياري)

```bash
export GRADLE_USER_HOME=/home/hatch/.gradle
gradle assembleRelease   # Gradle 8.9 + JDK 17
```

ملحوظة: الـ Gradle daemon محظور في بيئة التطوير دي، فالبناء المحلي ممكن يفشل؛
البناء على GitHub هو الطريق المضمون.
